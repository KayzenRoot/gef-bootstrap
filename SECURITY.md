# Security Policy

## Supported versions
| Version | Supported |
| --- | --- |
| 1.0.x | Yes |

## Reporting
Do not publish credentials, tokens, private keys, personal secrets or exploit-sensitive private data in issues, PRs, logs or screenshots. For a suspected vulnerability, prepare a minimal reproduction with secrets removed and use GitHub's private vulnerability reporting feature when available for the repository. If private reporting is unavailable, do not disclose sensitive exploit details publicly; contact the repository owner through an established private channel.

## Assurance model
GEF uses fail-closed handling for unknown/conflicting security evidence. Hash integrity is not represented as cryptographic authentication unless separately proven. Release acceptance requires zero unresolved CRITICAL/HIGH findings under the governed acceptance contract.
