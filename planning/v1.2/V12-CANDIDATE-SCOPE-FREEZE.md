## 1. Product objective
Install one versioned startup-standard Bootstrap and automatically get a low-friction owner interview, source-authoritative product plan, relevant visual design, selective domain toolchains, rigorous Codex Marathon WOs, reproducible tests, quality and security gating, GitHub/ChatGPT audit, running local/product preview where applicable and an honest pt-BR status/forecast panel on every substantive development response. Optimize comparable accepted user functionality per effective Codex/hour and cost while meeting the same or stronger release assurance; do not optimize merely prompt size, PR count or lines changed.

### Universal GEF core — proposed REQUIRED features (subject to future technical admission)
C01 Guided project discovery: adaptive batch interview of 5-7 high-impact unanswered questions per round for NEW_PROJECT; gap-only review and prior approved source preservation for EXISTING_PROJECT; GUIDED / FAST / DEEP modes and owner-approved decision/assumption trail.
C02 Canonical project planning: product mission, personas, prioritized user journeys, Scope/DoD, requirements to proof, architecture/security/deployment/test specs, Decision IDs, owner-change impact and critical path; robust issue-backed scoped WOs and Source Pack checksum/continuity.
C03 Approved visual experience: for applications with user-facing UI, wireflow, style direction, owner review, semantic design tokens, responsive components and all relevant states (loading/error/empty/denied/offline). Functional, accessibility and visual proof before acceptance; preserve approved brownfield UI and never require an external SaaS.
C04 Marathon Engine/critical-path orchestration: long but reviewable dependency-ordered Codex-only execution waves with exact Context Lock, file ownership, bounded safe parallelism, resumption and wave checkpoints; no second code executor.
C05 Bug Hunter and requirement/invariant proof: static and contract-derived property tests, changed-risk mutation on justified portions, conservative unknown impact and minimized deterministic regression fixtures. Profile-specific domain adapters apply only when actually required.
C06 Delta Assurance 2.0, causal repair and flake control: validity-bound reuse of genuinely green receipts, changed-surface fast tests, bounded root-cause correction, independent blinded comparison with mandatory risk floors, no stale PASS or global mandatory gate pruning. Required exact-head full release proof always runs.
C07 Autonomous review/evidence: one consolidated independent ChatGPT exact-head audit at owner-approved boundaries with additional specialist review for defined HIGH_ASSURANCE risks. Codex self-report is not an independent review or proof. Preserve source-authoritative acceptance chain.
C08 Engineering Intelligence: comparable speed/quality/cost baselines, observable Codex and CI runtime, meaningful escaped defects, false positives, reopened work and confidence. No fabricated speedup, silent spend or incompatible cohort aggregation.
C09 Always-on reporting: M20/M21/M22/M23 single truthful compact pt-BR response contract on substantive dev turns: project/release/status and SHA/timestamp, accepted weighted percent and remaining scope where denominator valid, WO/issue/PR state, blocker/quality/required checks, last real change, next permitted step and M22 estimate with valid comparable samples or NOT_YET_BASELINED. Never calculate project progress from lines of code, docs count or unmerged drafts.
C10 Default installer and profile router: versioned startup profile with new/brownfield adoption, actual verified Git/stack detection plus owner-confirmed domain selection, scoped per-target-project tool installation, reversible upgrade/opt-out, Windows/Linux/macOS only where verified, cost/permission/entitlement doctor and representative real installable sample app.
C11 Release and reproducibility: build once where exact fingerprints permit, local/dev/CI compatibility, secret-safe artifact provenance when eligible, supply-chain/static/workflow controls and preview/real smoke/recovery where applicable. New services are justified by measured ROI; no blanket migration to Nx, Turborepo, Kubernetes or cloud.
C12 Operations feedback: for deployed apps, scope-appropriate health/reliability observability, privacy-safe defect reproduction, recovery/SLO and post-release bug-to-regression flow using existing GEF engines. No universal always-on hosted GEF runtime requirement.

D11 GAME + WEB3: explicitly justified onchain assets/settlement only, keep fast gameplay and normal combat offchain, independently prove contract and server invariants and cross-boundary transaction event idempotency/finality/reorg, prevent duplicated offchain/onchain inventory credit, wallet signing UX without blocking the game tick. ## 2. Universal guardrails and anti-feature-bloat
- New proposals stop here for the V1.2 *ideation baseline*. A subsequently discovered release-blocking security defect or unsupported necessary requirement enters via explicit change control and new denominator epoch. New “interesting” technologies after this date default FUTURE/experimental; do not silently enlarge core v1.2.
- Profile routing is owner-approved, not inferred from dependency names or untrusted source comments. Existing project ADR/stack retains authority unless owner adopts the migration.
- Install the smallest toolchain into the target repository only, not all domain frameworks into GEF. Evaluate current license, true free-tier availability, system requirements, maintenance and security before using candidate tools. A claimed shortcut that misses HIGH/CRITICAL or expands protected data exposure is rejected.
- No claim of zero bugs, guaranteed speed gain, made-up maturity, blanket financial/legal compliance, automatically secure smart contracts, unsupported current cloud plan or forecast from fewer than valid M22 domain samples.
- Never treat planning docs, generated source pack drafts, unit test counts, raw CI runs, incomplete PRs or feature counts as implementation percentage.
- No real money/production asset transfer, deployment secret access, live provider subscription or irreversible data migration by a self-directed Codex run. Qualified independent audit and explicit authorized release step govern applicable high-risk apps.
- Avoid long interview bureaucracy: short adaptive batches, consolidate existing answers, display owner blockers, preserve source-of-truth, design approve before expensive UI implementation and show progress in every substantive response.
- Release timing guard: the required V1.2 core SHOULD be independently releasable even if high-risk optional conditional packs remain RESEARCH. No bundled claim that every chain/game engine/ledger is validated by one core install test.
