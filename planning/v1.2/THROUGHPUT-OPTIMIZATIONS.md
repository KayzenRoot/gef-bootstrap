# V1.2 — Throughput and Planning Optimization Research

Status: future candidate deltas; no implementation, no benchmark gain claimed. Prefer extending existing M14/M15/M17/M18/M24–M28/M43–M45/M63. Before adding a new runner/agent/cache, measure current V1.1 released baseline against identical Scope and DoD.

## First-principles throughput goal
Optimize end-to-end accepted useful application functionality per effective executor-hour, including discovery, design revisions, proof quality, CI/merge, deployment/preview and escaped defect remediation. Prompt length, raw code lines, number of PRs and tests executed are not output quality. Security, accepted source authority, deterministic exact-head evidence and HIGH_ASSURANCE remain hard constraints.

## Additional high-leverage first-party research candidates
S01 CRITICAL-PATH WORK PLANNER: extend M15 dependency DAG to prioritize unblocked requirements that remove the most downstream blockers, with explicit critical path and work-in-progress limit. Keep unrelated speculative tasks OUT_OF_SCOPE. Do not fuse risky unrelated domains into a mega-PR. Measure time from approved requirement to genuinely usable end-to-end feature.
S02 VERTICAL-SLICE COMPILER: compile related backend/UI/database/contracts/integration tests into a complete user workflow rather than shipping horizontal but unusable layers. Smaller valid PR boundaries are allowed inside long Marathon Work Order; final consolidated audit may span safely linked waves with auditable intermediate proof.
S03 DECISION-LATENCY LEDGER: identify hours lost waiting on unresolved product decisions, dependency ambiguity and review gate handoffs. Ask the single highest-impact batch of interview questions before Codex; freeze answers once, resume from affected delta rather than reinterviewing.
S04 REUSABLE GOLDEN-PATH PROFILES: version governed application archetypes (small web app, API, dashboard, persistence-backed app) with minimal required Source Pack, stack-appropriate dependencies, threat models, design tokens, tests, CI, deployment/recovery and sample vertical slice. New project can select a profile, but owner product requirements override defaults. Check versions/security/entitlements at install; no dependency bloat for unsupported profiles.
S05 CONTRACT-SUPPORTED PARALLELISM: build independent waves or test groups in parallel ONLY when file ownership, dependency DAG, environment/resource and proof isolation are verified. Codex is still the sole code executor; parallel subprocesses under Codex aren't a second independent author. Never allow two writers racing the same canonical checkpoint, migration or generated files.
S06 BUILD-ONCE / PROOF-MANY: when exact built artifacts are valid for test targets, use one content-addressed build and reuse immutable outputs across independent tests/checks. Fingerprint source, lockfile, compiler flags, runtime, OS, generated code and environment; untrusted forks never write privileged shared caches. Compare with current native TypeScript incremental build before adopting any orchestrator.
S07 RISK-WEIGHTED EXECUTION QUEUE: place cheap and high-signal gates first (source validity, static/type, changed unit, boundary integration) then only impacted expensive proofs; release and uncertain impact force required full regression. Use historical failures to PRIORITIZE ordering, never to suppress mandatory risk floors.
S08 REGRESSION MEMORY: high-value reproduction corpus for every critical discovered defect with minimized fixture/seed and exact contract binding, so correction permanently expands meaningful bug resistance. Curate and periodically prune duplicates only with proof, not raw test-count targets.
S09 STATE-MODEL ADVERSARIAL CHECKS: where state machines/money/auth/recovery matter, test explicit valid and forbidden transitions, invariants, idempotency, race and rollback; property/stateful model testing may expose errors example-based suites miss. Calibrate runtime.
S10 DYNAMIC DEPENDENCY UNCERTAINTY: handle plugin loaders, reflection/dynamic imports, generated code and shared test fixtures as conservative impact graph edges. Unknown boundaries widen validation instead of unsafe “affected only.”
S11 FAILURE-COST HEATMAP: combine cause-coded failures from Codex runs and live bug reports; design future invariants and stronger fast checks around costly recurring root causes. Never use opaque model risk prediction to overrule mandatory proof.
S12 TOOL/FRAMEWORK SUBSTITUTION LAB: compare build/test/task orchestrators only after representative experiments. Nx affected/local caching (https://nx.dev/docs/features/run-tasks and https://nx.dev/docs/features/ci-features/remote-cache) and Turborepo caching (https://turbo.build/repo/docs/crafting-your-repository/caching) are optional for fitting monorepos; compare native TypeScript incremental builds, GitHub Actions cache, task graph correctness, security and upkeep. Cloud features or paid plans need separate entitlement proof; local cache preferred first.
S13 DETERMINISTIC SERVICE SIMULATION: MSW or equivalent mocked API at UI boundary, virtual time and reusable test fixtures for faster reproducible component tests; still retain a small real backend integration suite and true app E2E. Mock-only green never proves real integration.
S14 COST-AWARE MATRIX SCHEDULER: distribute expensive test suites intelligently across self-hosted/local and GitHub-hosted resources by trust, risk, hardware capability and actual cost; cancel only superseded PR-only runs, never mandatory push-range secret scans, release proof or unrelated workflows. Public/free compute has quota/OS/runner exceptions to verify.
S15 EVIDENCE-DRIVEN REVIEW SCHEDULER: avoid constant manual review for low-risk intermediate steps, but material contract/security/state changes require earlier targeted audit; produce one consolidated exact-head full review at approved boundary. Independent HIGH_ASSURANCE review still mandatory.
S16 AUTOMATIC DOC DELTA PROPOSAL: from code diffs and accepted test evidence, propose affected Source Pack sections and checkpoint delta; Codex may generate proposed evidence during execution but may not independently promote canonical truth. ChatGPT audits and updates only proven docs after APPROVED.
S17 SELF-HEALING DEVELOPMENT ENVIRONMENT (bounded): run preflight doctor for Node/npm/OS/runners/tool binary/browser/db container; offer reversible exact commands when drift detected. Do not silently install external paid or privileged software; confirm destructive actions.
S18 TASK BUDGET SENTRY: cap exploration, retries and mutations that cannot justify their marginal bug detection, after preserving risk-required tests; measure actual wall-clock/CPU/CI and review time. No arbitrary timeout overrides a mandatory release gate.

## Optimizations to avoid
- All-in-one giant prompts with unrelated modules, unreviewable source surface, stale context and no midwave checkpoint.
- Frequent whole-monorepo builds after every tiny fix when exact built artifacts and proof bindings remain valid.
- Converting finished prototype mockups into “release-ready app” without backend/security/integration tests.
- A second code author/tool chain that violates approved Codex-only contract.
- Unconditional Nx/Turborepo/Vitest/Biome/Storybook/Semgrep installation on every app.
- Skipping or masking release tests, repeating identical failing commands, prematurely promoting speculative checklists as percentages.

## Benchmark design
Baseline released V1.1 on comparable NEW_PROJECT and EXISTING_PROJECT fixture apps with frozen acceptance criteria. Test one optimizer or compatible cluster at a time, compare deterministic workload, elapsed and CPU/CI costs, accepted functionality, material defect escape, flaky rate, correction count, operator design revisions, false positives, cache invalidations and full release pass. A faster run with worse security or more escaped material defects FAILS. Keep confidence intervals/unknowns distinct from hard policy thresholds.

## Risks and readiness
Proof/cache poisoning, build-output contamination, cross-OS case and path differences, derived status without provenance, over-scoped parallel edits, premature architectural defaults, false confidence from mocks, UI snapshot approval bias, heavy test tool overhead. Each experiment includes injection tests and rollback plan before promotion. Any newly found material defect must lead to a narrower correction and an updated regression proof.
