# GEF Bootstrap V1.1 Scope

Status: `AUTHORIZED_FOR_PLANNING`
Release line: `1.1.x`
Stable production baseline: `v1.0.0`
Development branch: `release/1.1`

## Release invariant
`main` remains the currently production-approved release. Work for V1.1 MUST remain outside `main` until V1.1 satisfies its release Definition of Done, exact-head audit, production acceptance, and promotion gate. If a V1.0-compatible production defect requires correction first, ship it independently as `1.0.x` and forward-port the correction into `release/1.1`.

## Objective
Turn the complete V1 governance/runtime foundation into a faster, installable, upgradeable and executor-optimized developer product without weakening V1 evidence, safety, compatibility or fail-closed behavior.

## NECESSARY scope
1. Production-grade GEF CLI surface: `gef init`, `gef adopt`, `gef doctor`, `gef status`, `gef upgrade`.
2. Professional distribution/install path, while preserving source-workspace operation where compatible.
3. Upgrade Engine hardening with preservation-first migration, dry-run, compatibility checks and rollback/roll-forward evidence.
4. Self Doctor 2.0 covering runtime/toolchain, repository, Source Pack, Git/GitHub/CI, compatibility, integrity and actionable remediation.
5. Codex/Executor Acceleration Pack that compiles minimal deterministic execution context rather than requiring broad repository rediscovery.
6. Context Compiler optimization: relevance selection, fingerprints, delta context, cache/reuse and explicit invalidation.
7. Incremental Validation/Test Impact: select affected checks fail-closed, with escalation to broader assurance when impact is uncertain.
8. Proof Reuse: reuse only still-valid evidence bound to compatible fingerprints, lineage and policy; never manufacture production credit.
9. Migration/Compatibility Matrix across supported GEF versions and project adoption modes.
10. Local performance telemetry for execution duration, context volume, test volume, cache/proof reuse, retries and comparable before/after benchmarks.
11. Release-channel governance enforcing stable `main`, isolated next-release development and governed hotfix forward-porting.
12. Cross-platform assurance for supported Windows, Linux and macOS paths.

## IMPORTANT but non-blocking unless promoted by governed change
- Richer interactive CLI UX.
- Additional executor adapters beyond the generic/Codex-compatible execution contract.
- Advanced historical analytics dashboards.

## FUTURE
- Adaptive planning learned from historical executions.
- Automatic assurance-intensity tuning beyond deterministic policy bounds.
- Autonomous Work Order optimization using historical outcome learning.
- V2 breaking-contract redesign.

## OUT OF SCOPE
- Breaking V1 public contracts merely for cleanup.
- Rewriting accepted V1 history or moving the `v1.0.0` tag.
- Making experimental V1.1 work the default production release before acceptance.
- Broad unrelated refactors.
- Cloud dependency as a requirement for core local operation.

## Release acceptance summary
V1.1 is promotable only when all NECESSARY items are functional, tested, documented, benchmarked where applicable, cross-platform validated, security/integrity reviewed, migration/recovery proven, and exact-head Production Acceptance reports CRITICAL=0 and HIGH=0.
