# Proposed V1.2 Scope Delta

**State:** `PROPOSED / NOT_CANONICAL`

## In scope

### Core V1.2
1. Guided owner discovery feeding current Source Pack/Planning/Decision/Scope authorities.
2. Canonical planning composition with explicit requirements, acceptance proofs and change-impact links.
3. Visual-experience contract for UI-bearing projects; tooling activated only by profile.
4. Marathon orchestration over existing M14/M15/M17/M18/M63 primitives.
5. Bug Hunter adapters for contract/property proof and bounded mutation analysis.
6. Delta Assurance 2.0 with proof invalidation, causal repair receipts and flake control.
7. Review/evidence packet aligned to owner-operated NOT_INDEPENDENT exact-head audit.
8. Engineering Intelligence using comparable accepted-functionality/time/cost/quality evidence.
9. One compact status composition over current response/progress/estimation/project-status engines.
10. Owner-confirmed profile routing and reversible/scoped installation over existing profile/adoption/capability/install engines.
11. Reproducible release and recovery extensions over current release/integrity/upgrade authorities.
12. Operations-feedback contract with profile-conditional activation.

### Release-blocking reference profile
`WEB_APP_API`.

The reference profile must prove the complete V1.2 core journey on a controlled, reproducible target.

## Conditional, non-release-blocking by default

- data-heavy apps;
- SaaS subscription/usage;
- SaaS enterprise/tenant;
- financial value movement;
- Web3 EVM;
- Web3 Solana;
- Web3 data security;
- games 2D/3D;
- multiplayer/MMO;
- game + Web3;
- AI-native targets.

`WEB3_EVM` is second priority, not part of the default V1.2 release denominator.

## Experimental/future by default

- formal/deep symbolic proof beyond bounded practical assurance;
- confidential/onchain compute research;
- enterprise/global/multi-region/all-chain/MMO-scale claims without real workload evidence;
- jurisdiction-specific regulatory/tax certification engines;
- framework/vendor/platform swaps without measured ROI.

## Out of scope for core V1.2

- real-money production deployment;
- mainnet real-asset deployment;
- custody operations;
- country-specific legal/compliance certification;
- automatic paid-service procurement;
- a hosted always-on control plane as a universal dependency;
- second copies of existing context, execution, proof, status or release engines.

## Release denominator

Core V1.2 acceptance requires:
- WO-001 through WO-006 admitted and completed;
- C01-C12 acceptance contracts satisfied;
- WEB_APP_API reference profile production evidence satisfied;
- no CRITICAL/HIGH blockers;
- all required repository checks green;
- release/recovery/provenance evidence complete.

Conditional packs do not block core release unless explicitly promoted into the denominator by a later owner decision.
